# 技术博客写作规范

> 本规范适用于开源鸿蒙PC社区技术博文撰写，发布前请逐项自查。

---

## 一、SEO 优化

想要技术博客被更多人观看、被更多搜索引擎捕捉，文章的优化非常重要。

### 1. 标题优化

- 这是最重要的排名因素之一，重点展现**开源鸿蒙**、**命令行适配**等关键词。
- 标题要有吸引力，吸引用户点击。
- **长度**：控制在 **30 个字符**以内，避免在搜索结果中被截断。
- **H1 标签**：通常就是文章的标题，一个页面最好只有一个 H1，并包含核心关键词。

### 2. 内容质量

- **原创且有深度**：生产高价值原创内容，全面覆盖开源鸿蒙主题。
- **可读性强**：使用短段落、小标题（H2、H3）、项目列表和图片，让用户轻松阅读。
- **长度适中**：长文通常更容易排名，但前提是内容充实，而非堆砌。

### 3. 图片优化

- 为图片添加描述性的 **ALT 标签**，帮助搜索引擎理解图片内容，也是图片搜索的重要来源。
- 压缩图片大小，提升加载速度。

### 4. 内部链接

- 在文章中链接到其他行业技术网站、开发者社区等。
- 这能延长用户在网站的停留时间，并传递页面权重。

---

## 二、大模型搜索引用优化

文章被大模型搜索引用，需要加强内容的**结构化**、**权威性**及**机器可读性**。

### 1. 强化内容结构与信息密度

- 采用严谨的层级标题（H1-H3）明晰文章脉络。
- 广泛使用列表与表格呈现步骤、特征与数据，便于 AI 精准抓取。
- 于文首增设**摘要**，扼要概括核心论点与结论，助力 AI 快速理解。

### 2. 构建权威性与可信度

- 在论述中主动引用并链接至权威机构、学术论文等高质量外部信源。
- 显著位置展示作者及机构的专业背景与资质。
- 保持客观、中立的行文风格，提供可验证的数据与证据。

### 3. 部署结构化数据

- 需为每篇文章添加 **Schema.org** 标记（如 `Article` 或 `BlogPosting`）。
- 此举能以标准化格式，向 AI 明确标识文章的标题、作者、发布日期、核心正文等关键元素，极大提升被识别与引用的效率。

## 四、常见问题与解决（排障知识库）

> 记录开源鸿蒙 PC 社区博文系列在开发 / 适配 / 发布过程中遇到的典型问题与解决思路，供后续文章复用。统一按「现象 → 根因 → 排查路径 → 解决办法」记录，涉及部署问题的条目必须先用设备侧证据（hdc 实测）排除根因，再下结论。

### 4.1 鸿蒙部署：HAP 推送失败 ErrorCode:00404039「创建临时目录失败」

- **现象**：DevEco Studio 部署 HAP 报 `execute sendRemoteCommand exception / ErrorCode:00404039 / 在HAP推送操作期间创建临时目录失败`，出错步骤为 `hdc shell mkdir data/local/tmp/<hash>`。
- **根因**：本地 hdc server 长时间运行进入病态、设备会话损坏。新起的 hdc 客户端连它报 `Connect server failed`；DevEco Studio 虽保持连接，但底层设备会话已坏，`hdc shell mkdir` 在坏会话上失败，DevEco 只把错误包装成 00404039。
- **排查路径**：先排除设备侧，别急着归因设备——`hdc shell df -h /data`（空间）、`hdc shell ls -ld /data/local/tmp`（权限）、重跑失败命令 `mkdir -p /data/local/tmp/zz_test`（功能）。实测空间充足、权限可写、命令可执行后，才转向本地 hdc 链路。
- **解决办法**：
  ```bash
  hdc kill && hdc start      # 重启本地 hdc server
  hdc list targets -v        # 确认设备重新在线
  ```
  重启后 DevEco Studio 自动重连，重新部署即成功。

### 4.2 鸿蒙部署：hdc 命令找不到 / 多设备条目需指定

- **现象**：终端执行 `hdc` 报 `command not found`；`hdc shell` 报 `need connect-key? please confirm a device`。
- **根因**：hdc 未加入系统 PATH（DevEco Studio 内置 hdc 在应用安装目录内）；hdc 可能同时注册 TCP 与 USB 两个设备条目，要求明确选择目标。
- **解决办法**：
  ```bash
  # 定位 DevEco Studio 内置 hdc 并加入 PATH
  export PATH="/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains:$PATH"
  # 多设备条目时用 -t 显式指定目标设备
  hdc -t <target-id> shell ...
  ```

### 4.3 three.js：r185 移除 Color.distanceTo 导致运行时 TypeError

- **现象**：前端运行报 `m.color.distanceTo is not a function`。
- **根因**：three.js r185 移除了 `Color.distanceTo`，而生成 / 旧代码仍调用该 API。
- **排查路径**：先核对当前安装的 three 版本（`package.json` 中 `three` 依赖），确认 API 是否已被移除。
- **解决办法**：最小修改，用手写欧氏距离替换收敛判断：
  ```js
  const dx = a.r - b.r, dy = a.g - b.g, dz = a.b - b.b
  const dist = Math.sqrt(dx * dx + dy * dy + dz * dz)
  ```

### 4.4 前端资源跑在鸿蒙 WebView 时的自包含降级

- **现象**：构建后的前端资源在鸿蒙 PC（ArkWeb WebView）加载后无 Electron 能力，无法走 IPC。
- **根因**：鸿蒙端是 WebView，没有 `window.electron` / `ipcRenderer`，也没有 dev server。
- **解决办法**：用 `isEE` 判定运行环境，非 Electron 时降级到内嵌配置 + 截图预览 modal；Vite `base:'./'` + hash 路由保证产物以 resfile 相对路径加载。
  ```js
  const isEE = !!(window.electron && window.electron.ipcRenderer)
  ```
